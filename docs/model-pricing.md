# 模型价格与成本完整性

设置中的“模型价格”位于“高级”之前，属于同一侧栏分组；页面使用原生列表，服务商名称与模型 ID 保持原文，仅展示 OpenAI、Anthropic、xAI 三家原始服务商条目与对应内置价格，使用与 Skill / MCP 管理一致的固定 Codex、Claude、Grok tabs 分别显示，初始为 Codex，不提供其他厂商入口，不展示第三方代理或其他服务商的同名模型；每个 tab 默认显示该商全部模型，包含缺价条目，切换 tab 清空搜索、状态筛选、排序与详情并重置分页；搜索按名称或 ID，排序按名称、输入或输出价格，每页最多构建 100 行，目录或筛选条件不变时复用已排序结果

## 同步与持久化

`modelPricing` 是 Go 偏好中的独立对象，默认自动同步开启、频率 3600 秒；对象或字段缺失时使用默认值，显式 `false` 必须保留，默认对象可省略；自定义频率为 900 至 604800 秒，非法输入显式报错，未知字段按现有 codec 规则保留；设置沿用异步保存及失败回滚，无额外保存按钮；自动开关、预设与自定义频率、完整同步状态放在 tabs 右侧“频率设置”按钮打开的原生弹窗中，设置对全部三家服务商共同生效，正文可滚动，底部完成按钮固定，关闭弹窗不取消同步任务，离开模型价格页时关闭弹窗

models.dev 提供聚合的公开 Token 参考目录，展示投影只取 providerID 精确为 `openai`、`anthropic`、`xai` 的条目，不将其描述为供应商官方实时接口；下载、解析与缓存仍保留通用目录格式，网络使用应用保存的代理策略；同步不发送会话日志或账号凭据，不因失败自动直连；自动关闭后仍可手动同步，同步中禁止重复启动；页面显示上次检查、成功同步、实际价格变化、下次同步、当前版本与错误，完整版本可在提示或详情查看

缓存与内置表承担离线展示与估算，失败时保留最后成功结果；目录数据版本与价格版本分开，展示名称或语言变化应更新 UI 数据版本，价格实质变化才触发相应成本重新估算；设置窗口关闭后通过取消与 generation 检查丢弃旧结果

## 目录价与实际计价

首版只列美元 / 百万 Token，不声称覆盖图像、视频等全部模态费用；每个价格字段可缺失，缺失显示 `—`，明确的零价显示 `$0`；不通过零值填补缺价

实际计价由各供应商包决定，不将远程基础价当作完整规则；已核实的上下文档位、严格大于或大于等于的边界、缓存写入 5 分钟与 1 小时、Fast 和地区倍率用结构化规则保留；远程资料不足以确定必要费率或规则时，相关 Token 保持未定价；详情分别解释目录参考、实际来源、版本与规则，不解析英文说明串来伪造翻译

## 完整性与界面

`usage.Summary`、每日、模型、项目与来源行附带 `UnpricedTokens`；会话项同样附带该计数；部分已计价金额保留，但标为“部分成本”，全部缺价不显示虚假的 `$0`；已知免费仍显示 `$0`

总量只按 `ConfidencePartiallyPriced` 或 `UnpricedTokens > 0` 标记部分计价，`price-source:*` 只用于来源信息；未知模型、缺必要价、缺 Fast 价格或阶梯边界不明分别显示可读原因，完整未定价模型清单不受模型摘要最多八行的限制；损坏日志或扫描失败另列为扫描提示，不能把它们归为价格缺失

历史会话的 API 等价成本按当前价格重新估算，并展示当前价格版本；这属于本机用量的参考估算，不改 Credits、订阅额度、reset credits 或上游实际账单的口径

## 兼容与验收

旧 summary schema 的字段缺失按兼容读取规则处理，保留旧 fixture，不重写历史日志；新 JSON 中未定价计数是派生成本元数据，不能据此修改官方会话或账号文件

自动测试覆盖偏好默认与边界、缺价和零价、分页与筛选、异步取消、保存失败、部分金额与完整原因清单；离屏截图只验证原生视图布局，不代替三端安装、真实代理、桌面或升级验收；本文不代表版本已公开发布

## 实现规模与目标例外

本次新增文件均少于 300 行，既有较长文件只承载局部改动；函数长度 50 行是默认目标，当前少量函数超过该目标，不能据此声称所有函数均不超过 50 行

`settings_pricing_dialog.go` 将三家固定 tabs、同步设置弹窗及同步状态按原生界面职责集中组织，弹窗直接沿用原有即时保存与失败回滚；`live_pricing_catalog.go` 的 `pricingRows` 在一次目录构建中完成不可变模型合并、别名规则说明与来源组装，输出供 UI 缓存复用；两者保留有明确边界的完整流程，未为压缩行数拆成需要反复传递布局或临时状态的通用层

`pricing.Manager.refresh` 将响应校验、版本和状态计算、原子保存、取消检查及快照发布集中为一个事务流程，先保存成功再发布，锁内外和发布顺序在同一处可见；超过函数长度目标属于本次实现有理由的例外，不代表放宽校验、错误传播或并发边界

本次没有新增通用规则引擎或第三方依赖，供应商规则仍由对应业务包执行，目录管理与原生 UI 仅交换结构化数据
